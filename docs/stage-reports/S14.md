# S14 Stage Report

## 需求确认

- 本 Stage 目标：在既有后端 GHCR + ECS 发布链路基础上，补齐 Web 管理端的 CI 门禁与 ECS 自动部署，并确保同次发布中 backend 先于 admin-web 启动。

- 关键实现点：
  - `Deploy Services To ECS` 工作流按 push 变更自动识别 backend/admin-web/edge-gateway 发布目标，并分别构建 GHCR 镜像。
  - deploy workflow 在 Runner 打包 deployment bundle 并上传到 ECS，再由 ECS 本地解压执行，避免服务器侧 `git clone/fetch` 受 GitHub TLS 或出网波动影响。
  - ECS 部署顺序固定为“backend -> admin-web -> edge-gateway”，统一入口 `edge-gateway` 最后启动，避免前端或小程序先切到未就绪的 API。
  - `scripts/start_admin_web.sh` 在启动前强制等待 backend 健康；`scripts/start_edge_gateway.sh` 再等待 backend 与 admin-web 都已健康，并校验端口变量格式。
  - `docker-compose.yml` 新增 `edge-gateway` 服务，公网只暴露网关端口；`mysql`、`backend`、`admin-web` 默认只绑定 ECS 回环地址。
  - `deploy/nginx/edge-gateway.conf` 把 `/` 转发到 admin-web，把 `/api` 转发到 backend，统一 Web 管理端与小程序的后端入口语义。
  - `sunflower-admin-web/nginx.conf` 收缩为纯静态站点服务，不再承担 API 反代职责。
  - `sunflower-backend/Dockerfile` 安装 `curl`，并把 backend healthcheck 统一为 `curl` 检查，避免镜像内缺少 `wget` 导致误判不健康。
  - `sunflower-miniapp/utils/mvp/api.js` 的默认 API 基地址与 `app.js` 对齐，避免 `http/https` 默认值不一致。
  - `pr-stage-gate.yml` 补齐 Node 20 环境和 Web 的 `npm ci/lint/test/build`，把 Web 纳入 CI 门禁。
  - 2026-03-12 deploy follow-up：`Deploy via SSH` 补齐可选的 `ECS_SSH_PASSPHRASE` 输入，并在文档中明确 SSH 握手失败时优先检查私钥/口令与 ECS `authorized_keys`。
  - 2026-03-12 deploy reliability hotfix：移除 ECS 上的 `git fetch origin main` 依赖，改为 Actions 侧上传 deployment bundle，避免 `GnuTLS recv error` 类仓库拉取失败阻塞发布。

## 人工复核步骤

1. 在 GitHub Secrets 中确认 `ECS_HOST`、`ECS_USER`、`ECS_PORT`、`ECS_SSH_KEY`、`DEPLOY_PATH`、`GHCR_USERNAME`、`GHCR_TOKEN`、`AUTH_TOKEN_SECRET` 已配置。
2. 在 GitHub Variables 中按需配置 `BACKEND_HOST_PORT`、`ADMIN_WEB_HOST_PORT`、`EDGE_GATEWAY_HTTP_PORT`；未配置时分别默认使用 `8080`、`18080`、`80`。
3. 向 `main` 推送一条同时命中 `sunflower-backend/**` 和 `sunflower-admin-web/**` 的提交，触发 `.github/workflows/deploy-backend.yml`。
4. 在 Actions 日志确认 workflow 先完成 backend 镜像构建与 `scripts/start_backend_with_mvp_seed.sh`，随后执行 `scripts/start_admin_web.sh`，最后执行 `scripts/start_edge_gateway.sh`。
5. 在 ECS 上执行 `docker ps --format '{{.Names}}' | grep 'sunflower-'`，确认 `sunflower-backend`、`sunflower-admin-web`、`sunflower-edge-gateway`、`sunflower-mysql` 均处于运行状态。
6. 访问 `http://<ecs-host>:<edge-gateway-http-port>/healthz` 确认返回 `ok`，再打开 `http://<ecs-host>:<edge-gateway-http-port>/`，确认管理后台可用且页面请求 `/api/health` 成功。
7. 在小程序中将 `SUNFLOWER_API_BASE_URL` 或 `app.globalData.apiBaseUrl` 设为同一 ECS 的统一入口地址，确认 `/api/*` 请求可正常返回。
