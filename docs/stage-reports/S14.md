- 本 Stage 目标：补齐后端与 Web 管理端的 CI/CD，完成 ECS 自动部署收口，并形成可复现的发布与回滚基线。

- 关键实现点：
  - `Deploy Services To ECS` 工作流按 push 变更自动识别 backend、admin-web、入口配置三类发布目标，并分别构建 GHCR 镜像。
  - `2026-03-13` follow-up：工作流拆分为 `detect-targets`、`build-backend`、`build-admin-web`、`deploy` 四段；backend 与 admin-web 在命中时可并行构建，避免同一次发布串行累加总时长。
  - `2026-03-13` follow-up：`detect-targets` 改为 `fetch-depth: 1` 检出当前 `GITHUB_SHA`，只在 push 场景按需抓取 `github.event.before` 对应 commit；backend/admin/deploy 三类 job 均改为 sparse checkout，减少无关代码拉取。
  - `2026-03-13` follow-up：backend/admin-web 镜像构建分别使用 `type=gha,scope=sunflower-backend` 与 `type=gha,scope=sunflower-admin-web`，解决默认 `scope=buildkit` 导致的 cache 互相覆盖问题。
  - backend 镜像构建阶段先执行 `dependency:go-offline` 预热依赖层，减少冷启动下载耗时；`2026-03-13` 起 GitHub-hosted runner 默认使用 Maven Central，只有显式传入 `MAVEN_MIRROR=aliyun` 时才启用 `sunflower-backend/.mvn/settings-docker.xml` 中的阿里云 Maven 公共镜像。
  - deploy workflow 在 Runner 打包 deployment bundle 并上传到 ECS，再由 ECS 本地解压执行，避免服务器侧 `git clone/fetch` 受 GitHub TLS 或出网波动影响。
  - ECS 部署顺序固定为“backend -> admin-web -> host nginx”，先切换后端，再切换前端，最后刷新宿主机入口，避免用户流量进入未就绪服务。
  - `scripts/start_admin_web.sh` 在启动前强制等待 backend 健康，并在 admin-only 部署时改为执行 `docker compose up -d --no-deps admin-web`，避免 Compose 触碰 backend 服务并回退到 `sunflower-backend:local` 本地构建。
  - `scripts/reload_host_nginx.sh` 会在刷新宿主机 Nginx 前再次确认 backend 与 admin-web 都已健康。
  - `docker-compose.yml` 收敛为 `mysql`、`backend`、`admin-web` 三个容器，全部只绑定 ECS 回环地址，不再创建容器化 `edge-gateway`。
  - `deploy/nginx/sunflower-host.conf.template` 把 `/` 转发到 `127.0.0.1:${ADMIN_WEB_HOST_PORT:-18080}`，把 `/api/` 转发到 `127.0.0.1:${BACKEND_HOST_PORT:-8080}`，统一 Web 管理端与小程序的后端入口语义。
  - `sunflower-admin-web/nginx.conf` 收缩为纯静态站点服务，不再承担 API 反代职责。
  - `sunflower-backend/Dockerfile` 安装 `curl`，并把 backend healthcheck 统一为 `curl` 检查，避免镜像内缺少 `wget` 导致误判不健康。
  - `sunflower-miniapp/utils/mvp/api.js` 的默认 API 基地址与 `app.js` 对齐，避免 `http/https` 默认值不一致。
  - `pr-stage-gate.yml` 补齐 Node 20 环境和 Web 的 `npm ci/lint/test/build`，把 Web 纳入 CI 门禁。
  - 2026-03-12 deploy follow-up：`Deploy via SSH` 补齐可选的 `ECS_SSH_PASSPHRASE` 输入，并在文档中明确 SSH 握手失败时优先检查私钥/口令与 ECS `authorized_keys`。
  - 2026-03-12 deploy reliability hotfix：移除 ECS 上的 `git fetch origin main` 依赖，改为 Actions 侧上传 deployment bundle，避免 `GnuTLS recv error` 类仓库拉取失败阻塞发布。
  - 2026-03-12 ingress consolidation hotfix：基于线上排查结果，发现宿主机 `nginx.service` 已占用 `0.0.0.0:80`，因此收敛为“宿主机 Nginx 唯一公网入口”，移除容器 `edge-gateway`，避免重复抢占 80 端口。

## 人工复核步骤

1. 在 GitHub Secrets 中确认 `ECS_HOST`、`ECS_USER`、`ECS_PORT`、`ECS_SSH_KEY`、`DEPLOY_PATH`、`GHCR_USERNAME`、`GHCR_TOKEN`、`AUTH_TOKEN_SECRET` 已配置；若私钥带口令，再确认 `ECS_SSH_PASSPHRASE`。
2. 在 GitHub Variables 中按需配置 `BACKEND_HOST_PORT`、`ADMIN_WEB_HOST_PORT`、`MYSQL_HOST_PORT`；未配置时分别默认使用 `8080`、`18080`、`3306`。
3. 向 `main` 推送一条同时命中 `sunflower-backend/**` 和 `sunflower-admin-web/**` 的提交，触发 `.github/workflows/deploy-backend.yml`。
4. 在 Actions 日志确认先执行 `detect-targets`，并且 checkout 不再出现 `fetch-depth: 0`；若是 push 触发，只额外抓取一次 `github.event.before`。
5. 在同一次 run 中确认 `build-backend` 与 `build-admin-web` 作为独立 job 并行执行；backend 日志使用 `scope=sunflower-backend`，admin-web 日志使用 `scope=sunflower-admin-web`。
6. 在 backend 构建日志确认默认下载源为 Maven Central，而不是 `maven.aliyun.com`；只有显式切换 `MAVEN_MIRROR=aliyun` 时才应看到阿里云镜像。
7. 再向 `main` 推送一条只命中 `sunflower-admin-web/**` 的提交，确认 deploy 日志中出现 `deploying admin web second`，且 `scripts/start_admin_web.sh` 只输出 admin-web 的 `pull`/`up --no-deps` 路径，没有出现 `Starting backend service with local build`。
8. 在 ECS 上执行 `docker ps --format '{{.Names}} {{.Ports}}' | grep 'sunflower-'`，确认只存在 `sunflower-backend`、`sunflower-admin-web`、`sunflower-mysql` 三个容器，且三者均只绑定 `127.0.0.1` 回环端口。
9. 在 ECS 上执行 `sudo nginx -T | grep -n '127.0.0.1:18080\\|127.0.0.1:8080'`，确认宿主机 Nginx 把 `/` 转发到 admin-web、把 `/api/` 转发到 backend。
10. 访问 `http://<ecs-host>/healthz` 确认返回 `ok`，再打开 `http://<ecs-host>/`，确认管理后台可用且页面请求 `/api/health` 成功。
11. 在小程序中将 `SUNFLOWER_API_BASE_URL` 或 `app.globalData.apiBaseUrl` 设为同一 ECS 的统一入口地址，确认 `/api/*` 请求可正常返回。
12. 按 `docs/S14-Release-Acceptance-Checklist.md` 逐项记录发布 SHA、Actions Run、验收人和验收结论；若发布失败，按 `docs/S14-Release-Runbook.md` 执行单组件或整体验证回滚。

## 风险与后续

- 当前已知风险：
  - 当前统一入口已完成同机路径转发，但仓库内尚未落 443/TLS；若要给小程序正式环境使用，仍需补齐域名与 HTTPS 终止。
  - 本地 Docker daemon 当前不可用，无法完成镜像级 `docker build` 冒烟；本次以 workflow YAML 解析、部署拓扑 YAML 校验、脚本行为校验和 Maven/Compose 回归作为替代校验。
  - 宿主机 Nginx 配置现在由 deploy workflow 覆盖，部署用户必须具备 `root` 或 `sudo` 权限；若后续 ECS 的系统服务策略收紧，需要同步调整发布权限。
  - `GHCR_TOKEN` 若过期或权限回收，会导致 ECS 拉镜像失败；需纳入凭据轮换与告警策略。
  - 当前 GitHub-hosted runner 已回到 Maven Central；若后续进入阿里云 self-hosted runner 阶段，再引入阿里云 Maven 镜像或 registry cache 时，需要同时验证 checkout 成本与镜像源收益。
  - admin-only 部署现在依赖现有 backend 已经健康；如果服务器上 backend 被手工删掉或已失效，前端部署会按设计直接失败，需要先补一次 backend 发布。
  - 当前工作站默认 `node v18.4.0 / npm 8.12.1` 低于 `sunflower-admin-web` 的本地运行要求；若开发机未预装 Node 20，需使用 `npx -y -p node@20 npm ...` 或显式安装 Node 20.19+ 后再执行 Web 测试。
- 下一 Stage 建议：
