# S15 Stage Report

## 需求确认

- 本 Stage 目标：将住宿订单从单一 `status` 重构为 `bookingStatus + paymentStatus + afterSaleRequest` 三层模型，并同步用户端、管理端、API 文档与测试。
- 本 Stage 边界（不做）：不接入真实支付/退款网关，不实现异步退款回调，不引入完整后台账号/RBAC。

- 关键实现点：
  - 后端新增 `BookingStatus`、`PaymentStatus`、`AfterSaleRequestType/Status` 和 `order_after_sale_requests` 表。
  - 订单 DTO/Admin DTO 新增 `bookingStatus`、`paymentStatus`、`latestAfterSale*`、`rescheduleCount`、入住/离店/失约时间字段，并保留兼容 `status/statusLabel`。
  - 用户端改期/退款改为“提交申请”；管理端新增审批、入住、离店、失约接口；后台直接改期/退款接口保留兼容。
  - 管理端订单页改为展示分层状态，支持待审批申请、后台直接改期/退款、办理入住/离店、标记失约。
  - 小程序订单页按组合状态约束按钮，提交改期/退款后显示“申请已提交”，并展示主状态/支付状态/售后状态。

## 人工复核步骤

1. 小程序创建订单并支付，确认订单详情返回 `bookingStatus=CONFIRMED`、`paymentStatus=PAID`。
2. 小程序发起改期或退款申请，确认订单页显示“处理中”，按钮被禁用，入住日期未立即变更。
3. 管理端打开同一订单，分别验证“同意申请/拒绝申请/办理入住/办理离店/标记失约”动作与状态展示同步更新。
