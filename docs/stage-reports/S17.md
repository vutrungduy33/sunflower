# S17 Stage Report

## 需求确认

- 本 Stage 目标：替换管理端静态 `app.admin.auth.token`，交付真实后台账号体系，支持手机号 + 密码登录、短信首次激活、短信重置密码、修改密码、退出登录，以及最小角色 `ADMIN/OPERATOR`。

## 人工复核步骤

1. 准备 `ADMIN_ACTIVATION_ALLOWLIST=13800000000:admin,13900000000:operator` 和腾讯云短信配置，打开管理端 `/activate`，对白名单手机号发送激活码并设置首个密码，确认成功后直接进入后台。
2. 在 `/login` 使用手机号 + 密码登录，刷新页面后确认系统通过 `/api/admin/account/me` 恢复登录态；点击右上角退出后，再访问后台业务页应被重定向回登录页。
3. 针对同一账号连续输入 5 次错误密码，确认提示“密码连续错误次数过多，请 15 分钟后再试”；锁定期间使用正确密码仍被拒绝。
4. 打开 `/reset-password`，完成短信验证码重置密码；成功后检查旧 token 访问 `/api/admin/account/me` 返回 401，新密码可正常登录。
5. 在已登录状态进入“修改密码”，修改成功后确认旧 token 失效；随后分别使用 `ADMIN` 和 `OPERATOR` 账号访问房型、价格库存、订单、经营概览页面，确认当前业务页都可进入。

## 风险与后续

- 当前已知风险：
  - 正式环境仍依赖 `ADMIN_ACTIVATION_ALLOWLIST` 与腾讯云短信签名/模板等外部配置到位；配置缺失时 backend 会按设计直接启动失败。
  - 当前角色模型只收口到 `ADMIN/OPERATOR` 共用现有业务菜单，尚未进入完整 RBAC 或菜单级裁剪。
  - 管理端短信与账号链路目前主要依赖后端集成测试和 Web 单测，首次激活、短信下发、锁定提示等仍建议在真实环境做一轮端到端回放。
