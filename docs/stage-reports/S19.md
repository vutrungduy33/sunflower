- 关键实现点：
  - 生产运行配置从 GitHub Secrets 挪到 ECS 本地 `.env.prod`，GitHub Actions 只保留 SSH/GHCR 等部署通道凭据，并在部署时生成 `.release.env` 承载镜像与发布元信息。
  - `docker-compose.yml` 改为通过 `env_file` 读取 `.env.prod` / `.release.env`，后端数据库映射、管理端短信与小程序微信配置全部收口到服务器本地环境文件。
  - 新增 `validate_prod_env.sh`、`deploy_backend.sh`、`deploy_admin_web.sh`、`deploy_prod.sh`、`bootstrap_prod.sh`，把“首次初始化/可选 seed”和“日常 prod 发布”彻底分开。
  - `deploy-backend.yml` 增加 `workflow_dispatch` 输入 `target / image_tag / run_seed`，支持自动发布、按目标重发以及基于历史 GHCR tag 的标准回滚。
  - 2026-03-26 热修：`deploy-backend.yml` 不再先打包并再要求远端存在 `deploy-bundle.tgz`；改为直接上传部署所需文件，并在 SSH 步骤校验 `docker-compose.yml` / `scripts/validate_prod_env.sh` 已到位，避免 `Upload deployment bundle` 成功后 `Deploy via SSH` 仍因找不到 tar 包失败。
  - 2026-03-26 二次热修：为 `DEPLOY_PATH=~/...` 场景补齐路径归一化，统一把 SSH 步骤中的 `~/` 解析为 `$HOME/` 后再 `mkdir/cd`，避免 `scp-action` 已经把文件上传到家目录下的真实 deploy path，而 deploy 脚本却进入字面量 `~/...` 目录；同时在失败时输出当前 deploy 目录树，便于后续排查。
  - 2026-03-26 三次热修：`appleboy/ssh-action` 在 `script_stop: true` 下会为脚本每一行自动插入退出码守卫，多行函数定义会被这些守卫打断并触发 bash 语法错误；本次把 deploy path 归一化改写为 parse-safe 的单行 `case` 语句，并使用 `${DEPLOY_PATH#\~/}` 显式移除字面量 `~/` 前缀，兼顾 action 的脚本注入限制与真实 home 路径解析。
  - 2026-03-26 四次热修：`script_stop` 对多行 `if/else` 也有副作用，`else` 分支开头注入的守卫会继承前一个条件测试返回的 `1`，从而把 `DEPLOY_TARGET!=bootstrap` 这种正常分支选择误判为失败；本次将收尾发布分支拆成两个无 `else` 的条件判断，保留语义同时避开守卫误杀。
  - 2026-03-26 五次热修：`.env.prod.example` 同时承担“本地 compose 渲染样板”和“服务器 `.env.prod` 模板”两种用途，旧样板中的 `RELEASE_ENV_FILE=.env.empty` 会在部署脚本 `source .env.prod` 后覆盖默认 `.release.env`，导致 `BACKEND_IMAGE` / `ADMIN_WEB_IMAGE` 回退为空并触发本地 build；本次在 `load_runtime_envs` 中固定保留调用侧的 release env 路径，并去掉样板文件里的该配置，确保运行时始终以 `.release.env` 为准。
  - 宿主机 Nginx 模板升级为正式域名 + HTTPS：`80 -> 443` 跳转，`443 ssl` 上转发 `/api/*` 到 backend、`/` 到 admin-web，并要求 `.env.prod` 提供证书路径。
  - 小程序默认 API 地址不再硬编码公网 IP / `http`，统一收口到 `sunflower-miniapp/utils/mvp/runtime-config.js` 的 `DEFAULT_API_BASE_URL`，便于发布前替换正式 `HTTPS` 域名。
