# S19 Stage Report

## 需求确认

- 本 Stage 目标：清理正式上线前的部署与域名阻塞项，统一 prod 配置归属，拆分 bootstrap/常规发布流程，并把宿主机入口、小程序默认 API 地址和 GitHub Actions 发布接口收口到正式 HTTPS 域名方案。

- 关键实现点：
  - 生产运行配置从 GitHub Secrets 挪到 ECS 本地 `.env.prod`，GitHub Actions 只保留 SSH/GHCR 等部署通道凭据，并在部署时生成 `.release.env` 承载镜像与发布元信息。
  - `docker-compose.yml` 改为通过 `env_file` 读取 `.env.prod` / `.release.env`，后端数据库映射、管理端短信与小程序微信配置全部收口到服务器本地环境文件。
  - 新增 `validate_prod_env.sh`、`deploy_backend.sh`、`deploy_admin_web.sh`、`deploy_prod.sh`、`bootstrap_prod.sh`，把“首次初始化/可选 seed”和“日常 prod 发布”彻底分开。
  - `deploy-backend.yml` 增加 `workflow_dispatch` 输入 `target / image_tag / run_seed`，支持自动发布、按目标重发以及基于历史 GHCR tag 的标准回滚。
  - 宿主机 Nginx 模板升级为正式域名 + HTTPS：`80 -> 443` 跳转，`443 ssl` 上转发 `/api/*` 到 backend、`/` 到 admin-web，并要求 `.env.prod` 提供证书路径。
  - 小程序默认 API 地址不再硬编码公网 IP / `http`，统一收口到 `sunflower-miniapp/utils/mvp/runtime-config.js` 的 `DEFAULT_API_BASE_URL`，便于发布前替换正式 `HTTPS` 域名。

## 人工复核步骤

1. 在 ECS 部署目录放置真实 `.env.prod`，至少填好微信配置、管理端短信配置、`HOST_NGINX_SERVER_NAME`、`HOST_NGINX_TLS_CERT_PATH`、`HOST_NGINX_TLS_KEY_PATH`，然后在 GitHub Actions 手动触发 `target=bootstrap`。
2. 发布完成后访问 `https://<HOST_NGINX_SERVER_NAME>/api/health`，确认 backend 健康；再打开管理端正式域名，确认登录页与后台业务页都通过宿主机 Nginx 入口访问。
3. 使用 `workflow_dispatch + target=backend/admin-web/all + image_tag=<历史 sha>` 做一次回滚演练，确认 `.env.prod` 保持不变，仅 `.release.env` 与容器镜像版本切换。
4. 在小程序开发版/体验版将 `DEFAULT_API_BASE_URL` 或 `SUNFLOWER_API_BASE_URL` 指向正式 `HTTPS` 域名，确认微信登录、手机号绑定、下单主链路可通过正式域名访问。
5. 在宿主机执行 `sudo nginx -t` 并检查 `/etc/nginx/sites-available/${HOST_NGINX_SITE_NAME}`，确认已经渲染出 `80 -> 443` 跳转和 `443 ssl` 转发配置。

## 风险与后续

- 当前已知风险：
  - 宿主机 HTTPS 证书仍需由运维先行签发并落到 `HOST_NGINX_TLS_CERT_PATH` / `HOST_NGINX_TLS_KEY_PATH`；未签发证书时 `reload_host_nginx.sh` 会按设计失败。
  - GitHub Actions 目前只能完成“发布脚本链路 + 本地校验”；真实 staging / production smoke test 仍需在目标 ECS 和微信后台配置完毕后执行。
  - 小程序正式域名默认值已去掉公网 IP，但发布前仍需要把 `sunflower-miniapp/utils/mvp/runtime-config.js` 中的占位域名换成真实 `HTTPS` 域名。
