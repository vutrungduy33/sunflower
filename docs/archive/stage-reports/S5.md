# S5 Stage Report

## 需求确认

- 本 Stage 目标：补齐小程序联调收口能力，统一登录态请求头、全局请求错误处理，并完善关键业务页（订单相关）的可回退导航体验。
- 本次热修目标：修复 macOS 开发者工具基础库 `3.14.2` 下点击“我的”页时出现的 `object null is not iterable` 渲染层报错。
- 本次扩展目标：识别并处理同类空值渲染风险，避免其他 MVP 页面在接口返回 `null`/残缺数组时触发同类异常。
- 本 Stage 边界（不做）：不改动后端 API 契约，不引入 S6（改期/退款）能力，不调整管理端功能。

- 关键实现点：
  - 新增可复用组件 `mvp-nav-actions`，提供“返回上一页 / 返回首页”双入口；当页面栈不足时自动降级到首页重启路由。
  - `mvp-nav-actions` UI 改为 TDesign `t-button` 承载，减少自绘样式并与小程序整体组件体系保持一致。
  - `mvp-nav-actions` 的“返回上一页”在上一页即首页时，改为走“返回首页”同路径（`reLaunch`），确保触发首页登录逻辑。
  - 将组件接入 `order-list`、`order-create`、`room-detail` 三个非 tab 业务页，避免用户从深层页面无法回退。
  - 在请求层补充登录态 header 注入（`Authorization: Bearer <token>`），并在登录成功后持久化 token。
  - 鉴权请求统一增加 `requireAuth`，本地 token 缺失时在请求发起前直接失败并返回统一提示文案。
  - 在请求层统一处理 401 场景：清理本地 token 并返回明确错误文案，便于页面统一兜底提示。
  - 登录态继续沿用 `SUNFLOWER_AUTH_TOKEN` 作为 storage key，保证与现有联调约定一致。
  - `mine` 与 `order-list` 页面 catch 分支改为优先展示后端/请求层错误文案，保证鉴权失败有显式提示。
  - 新增 `mvp` 子页面导航守卫脚本，约束所有非 tab 页面必须包含 `<mvp-nav-actions>`，并在 PR Gate 中执行防回归检查。
  - 在 `PR Stage Gate` 新增 `ripgrep` 安装步骤，避免 Runner 环境缺失 `rg` 时导致守卫脚本误失败。
  - 补齐 `home`、`booking`、`mine`、`order-list`、`order-create`、`room-detail` 的可视化加载失败态（含错误文案与“重新加载”按钮），避免仅 toast 提示导致可恢复路径不明确。
  - 将关键页面加载流程统一为 `loading/error/content` 三态，确保鉴权失效（401）、参数错误、服务异常时都有稳定兜底界面。
  - 在订单页与房型详情页对缺少参数场景改为页面级错误提示，避免白屏或无反馈状态。
  - 修复 `booking/index.wxml` 在开发者工具热重载下的条件渲染编译兼容性问题：将房型列表分支由 `wx:else` 调整为显式 `wx:if="{{rooms.length}}"`。
  - 修复 `mine/index.wxml` 在微信开发者工具（基础库 3.14.2）渲染层的条件分支稳定性问题：将 `wx:if/wx:elif/wx:else` 链改为显式 `wx:if` 条件，避免状态流切换触发 Framework inner error。
  - 在 `mine/index.js` 增加资料容错与加载序列保护：`profile.tags` 非数组时回退为空数组，并忽略过期异步请求结果，降低渲染层收到乱序数据更新的风险。
  - 2026-03-11 热修：将“我的”页首屏加载从 `Promise.all` 数组解构改为显式顺序请求，规避开发者工具渲染层对空值/数组解构的兼容性异常。
  - 2026-03-11 热修：为 `profile/orders/orderStats` 增加稳定默认值与 `hasProfile` 显式状态，模板不再直接依赖 `null` 资料对象做表达式求值。
  - 2026-03-11 热修：将手机号与标签文案收敛为 `profileMetaText`，减少 WXML 运行期表达式复杂度，降低 tab 快速切换时的渲染层异常风险。
  - 2026-03-11 扩展：新增 `sunflower-miniapp/utils/mvp/normalize.js`，统一提供首页、预订、发现、地图、订单、房型详情、下单页的数组/对象归一化能力。
  - 2026-03-11 扩展：`home`、`booking`、`discover`、`map`、`order-list` 改为先归一化接口返回，再写入 `wx:for` 数据源，避免把 `null` 直接传进渲染层。
  - 2026-03-11 扩展：`room-detail` 与 `order-create` 改为对 `room.tags / room.calendar / room.amenities / room.rules` 做稳定默认值处理，消除房型详情与下单页的同类空值风险。
  - 2026-03-11 扩展：`order-create` 与 `mine` 保持一致，去除首屏 `Promise.all` 数组解构；地图页额外忽略缺失经纬度的 POI marker，避免把脏数据渲染到地图层。

## 人工复核步骤

1. 在微信开发者工具中打开小程序工程并编译。
2. 从“我的”页进入“订单中心”，确认页面顶部可见“返回上一页 / 返回首页”。
3. 在“订单中心”点击“返回上一页”，确认回到来源页；再进入后点击“返回首页”，确认回到 `/pages/mvp/home/index`。
4. 当当前页上一页为首页（例如首页进入订单中心）时，点击“返回上一页”，确认行为与“返回首页”一致并触发首页登录流程。
5. 进入“房型详情”与“填写订单”页，确认同样具备上述双入口并可正常跳转。
6. 可选：在开发者工具 Storage 删除 `SUNFLOWER_AUTH_TOKEN`（其 value 可能为 `mock_token_*`）后，触发任一 `requireAuth` 页面请求（如订单中心/我的页），确认出现“登录态已失效，请重新进入首页”提示且不会无提示失败。
7. 在开发者工具中断网或把 API 地址改为不可达后，分别打开 `首页/预订/我的/订单中心/房型详情/填写订单`，确认页面展示错误态和“重新加载”按钮。
8. 恢复网络后点击“重新加载”，确认页面可恢复到正常内容态。
9. 在“预订”页输入关键词并查询，确认房型加载失败时展示错误态，恢复后可正常重新查询。
10. 在“我的”页频繁切换 tab 或快速来回进入页面，确认不再出现 `Framework inner error (expect FLOW_APPLY_PROPERTY...)`。
11. 在首页与“我的”页之间快速来回切换 5-10 次，确认不再出现 `object null is not iterable` 渲染层报错。
12. 可选：使用代理工具将 `/api/users/me` 或 `/api/orders` 的响应体改为 `null`，重新进入“我的”页，确认页面保持空态/默认统计且不会白屏或报渲染层异常。
13. 可选：分别将 `/api/content/home`、`/api/rooms`、`/api/posts`、`/api/poi` 的列表字段改成 `null`，重新进入首页、预订、发现、地图页，确认页面不再出现渲染层异常。
14. 打开房型详情和填写订单页，确认房型标签、设施、规则、价格日历即使后端字段为空也不会白屏或报错。
