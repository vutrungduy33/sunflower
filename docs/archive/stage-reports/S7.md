# S7 Stage Report

## 需求确认

- 本 Stage 目标：实现管理端房型、价格、库存维护 API，并提供最小可用的管理端身份校验。
- 本 Stage 边界（不做）：不实现管理端订单/售后处理（S8）、不创建 Web 管理后台工程（S9）、不引入正式 RBAC 或后台账号体系。

- 关键实现点：
  - 新增 `POST /api/admin/rooms`、`PATCH /api/admin/rooms/{id}`、`POST /api/admin/room-prices`、`POST /api/admin/room-inventory`。
  - 管理端鉴权采用静态 `Authorization: Bearer <admin-token>` 最小实现，未引入后台用户表，避免提前进入 RBAC 范围。
  - 房型创建/编辑独立使用 admin DTO，不影响已有小程序房型接口结构。
  - 价格接口按 `(room_id, biz_date)` 批量 upsert；库存接口仅修改 `totalStock`，自动保留 `lockedStock` 并重算 `availableStock`，避免破坏现有订单锁库存。

## 人工复核步骤

1. 启动后端后，使用 `Authorization: Bearer <admin-token>` 调用 `POST /api/admin/rooms` 创建新房型，确认返回自动生成的房型 ID 与完整房型字段。
2. 对该房型调用 `PATCH /api/admin/rooms/{id}` 更新名称或基础价，确认响应字段变化生效。
3. 调用 `POST /api/admin/room-prices` 与 `POST /api/admin/room-inventory` 写入指定日期价格和库存，确认返回 `updatedCount` 与明细。
4. 调用 `GET /api/rooms/{id}?checkInDate=yyyy-MM-dd` 或 `GET /api/rooms/{id}/calendar`，确认首日价格与库存已反映后台维护结果。
5. 对已有锁库存日期调用 `POST /api/admin/room-inventory` 将 `totalStock` 调低到小于 `lockedStock`，确认返回 `40900` 与“目标库存不能小于已锁定库存”。
