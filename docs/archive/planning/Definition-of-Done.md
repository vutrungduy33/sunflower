# Definition of Done（DoD）

> 当前 DoD 是普通交付检查清单，不再绑定 Stage 守卫、分支前缀或 PR 门禁。

## 1. 建议满足项

- [ ] 范围清晰：本次改动聚焦在用户请求的目标上
- [ ] 需求确认：已明确目标、边界、验收标准
- [ ] 代码完成：实现达到本次目标
- [ ] 自动化测试：至少执行 1 条可运行测试命令并记录结果
- [ ] 人工复核：提供可复现的手工验证步骤
- [ ] API 契约：保持兼容，或已同步调用端与 API 文档
- [ ] 文档更新：涉及用户、部署或 API 行为变化时已同步文档

## 2. Git / PR

- [ ] 分支命名清晰表达改动目的
- [ ] 提交信息说明主要变化
- [ ] 推送或合并前已运行与改动匹配的检查

## 3. 可选交付说明

需要较完整记录时，可说明：

1. 改动内容
2. 自动化测试
3. 人工复核步骤
4. API 契约影响
5. 风险与后续

## 4. 新增代码规范

- [ ] 新增/修改代码已遵循 `docs/Code-Conventions.md`
- [ ] 沿用现有目录分层与命名语义，未新开并行实现模式
- [ ] 已复用现有 UI、HTTP、DTO、状态和工具封装，未引入不必要的新框架
